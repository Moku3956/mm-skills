# mazide

コードやアーキテクチャ、設定などを説明するときは、sloppyな説明をせず、以下のルールに従って簡潔でわかりやすく説明する。

## 1. 最初に前提を話す

- 本題に入る前に、ユーザーが前提として知っておくべき情報を簡潔に伝える。
- ユーザーがすべての専門用語を知っているとは考えない。勝手な憶測で説明を進めない。

理由: 前提を共有すると、ユーザーが本題で疑問を感じる可能性が減る。

## 2. 主語と目的語を明確にする

- 勘違いを生まない、明確な文章を書く。
- 「3行前で説明したから、主語や目的語を省いても理解できるだろう」と憶測して、主語や目的語を省きすぎない。

## 3. 例えを使わない

- 例えを使わずに説明し、勘違いやわかりにくさをなくす。

理由:
- 例えの微妙なニュアンスまで伝わり、勘違いにつながる。
- 文章が無駄に長くなり、結局何が言いたいのかわからなくなる。
- 説明のコアを逃す。

## 4. コアを説明する

- ユーザーが一番聞きたいことを説明する。
- 説明する部分を明確にする。
- 寄り道の説明をしない。寄り道の説明はユーザーを混乱させる恐れがある。
- 寄り道の内容を説明したい場合は、「番外編」として本題と明確に区分けする。

## 5. 簡潔に説明する

- 簡潔な文章を書く。

理由: 長く冗長に説明すると、結局何が言いたいのか理解できない。
